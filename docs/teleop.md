# Teleoperation

`mfr3duo_teleop` is the interactive keyboard teleoperation tool for the Mobile FR3 Duo simulation. It links directly against `mfr3duo_mujoco` and owns its own `Simulation`; it does not communicate with a separately running `mfr3duo_sim` process.

Pinocchio is a dependency of the teleop tool only. The `mfr3duo_mujoco` library
target does not link against Pinocchio. Teleop uses a project-private Pinocchio
4.1.0 installation under `third_party/pinocchio/install` by default; a system
Pinocchio installation is not modified or used.

## Control model

The simulation runs continuously through `Simulation::start()`. The teleop loop runs at 100 Hz and converts keyboard input into robot-level commands. Motion integration uses the latest simulation timestamp rather than wall-clock loop time, so commanded joint, Cartesian, spine and gripper rates remain expressed per simulation second even when the physics scheduler runs slower than real time.

- Base: planar velocity command with an input timeout.
- Spine: position jogging generated by integrating a bounded velocity request.
- Grippers: width jogging generated by integrating a bounded width rate.
- Arms:
  - Joint mode: selected-joint velocity jogging integrated into a joint-position target.
  - Cartesian mode: 6D Cartesian twist converted to joint velocity with a damped-least-squares differential IK solve.

Both arm modes ultimately generate `ArmCommand` position targets and use the same `Simulation::write_command()` API.

Cartesian control uses the current measured arm and spine state to compute the Jacobian. Pinocchio loads the authoritative `mfr3duo_description/urdf/mfr3duo.urdf` model. The base frame is the fixed kinematic root for arm control; mobile-base world motion therefore does not change the meaning of base-frame Cartesian jogging.

The differential IK solve is:

```text
q_dot = J^T (J J^T + lambda^2 I)^-1 v
```

The resulting joint velocity is limited by both the teleop velocity setting and the limits from the Pinocchio model. Integrated joint targets are clamped to the URDF position limits with a small margin.

## Keyboard controls

Target selection uses uppercase keys:

```text
B  Base
L  Left arm
R  Right arm
S  Spine
G  Left gripper
H  Right gripper
```

Base:

```text
w/s  +X / -X
a/d  +Y / -Y
q/e  +Yaw / -Yaw
```

Arm joint mode:

```text
1..7  Select joint
-     Negative joint direction
=     Positive joint direction
M     Switch to Cartesian mode
```

Arm Cartesian mode:

```text
w/s  +X / -X
a/d  +Y / -Y
r/f  +Z / -Z

i/k  +Roll / -Roll
j/l  +Pitch / -Pitch
u/o  +Yaw / -Yaw

M     Switch to Joint mode
F     Switch Base / Tool reference frame
```

Spine:

```text
w/s  Up / Down
```

Gripper:

```text
o/c  Open / Close
```

Common:

```text
Space   Stop robot motion and resynchronize hold targets
Ctrl-R  Reset the simulation and resynchronize targets
Esc     Exit
```

Terminal keyboards do not expose reliable key-release events. Motion keys therefore use a short wall-clock input lease. Repeated key events refresh the lease; when it expires, the requested velocity becomes zero. This prevents a lost terminal input event from leaving the base or a joint jogging continuously. The lease deliberately uses wall time for operator safety, while motion integration uses simulation time.

## Build

The teleop tool is enabled by default. Install its private Pinocchio first:

```bash
./scripts/pinocchio.sh install
./scripts/pinocchio.sh status
```

The script bootstraps a project-private micromamba executable when necessary and
creates `third_party/pinocchio/install` with Pinocchio 4.1.0 and its runtime
dependencies. It does not activate an environment, edit shell startup files or
export global library paths.

Then configure and build normally:

```bash
cmake -S . -B build \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_PREFIX_PATH="$HOME/.local/romujoco"
cmake --build build -j
```

CMake requires the private Pinocchio 4.1.0 package and its
`pinocchio::pinocchio_parsers` target. It intentionally does not fall back to
an older system Pinocchio such as 3.4.0.

For a minimal library/simulator build without Pinocchio:

```bash
cmake -S . -B build \
  -DMFR3DUO_MUJOCO_BUILD_TELEOP=OFF \
  -DCMAKE_PREFIX_PATH="$HOME/.local/romujoco"
```

Run:

```bash
./build/mfr3duo_teleop
```

An explicit model pair can be selected when needed:

```bash
./build/mfr3duo_teleop \
  --scene /path/to/mfr3duo_description/mjcf/scene.xml \
  --urdf /path/to/mfr3duo_description/urdf/mfr3duo.urdf
```
